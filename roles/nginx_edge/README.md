# Role: nginx_edge

The internet-facing edge (00-architecture §4.5): TLS termination + load balancing
across the web tier, on edge1/edge2. `keepalived` floats the VIP across the pair next.

## What it does
- **Upstream `app_backend`**: web1:8080 + web2:8080, **`least_conn`**, each with
  `max_fails=3 fail_timeout=15s`; `proxy_next_upstream error timeout http_502 http_503`
  bypasses a dead backend within seconds (no 502s during a single-node outage).
- **TLS** on :443 (http2), **:80 -> :443 redirect**. Self-signed cert generated by the
  role (`subjectAltName` covers app.platform.lab, vip.platform.lab, and the VIP IP).
- **Proxy headers**: `Host`, `X-Real-IP`, `X-Forwarded-For`, and **`X-Forwarded-Proto
  https`** — what the web vhost's `set_real_ip_from` and the wp-config shim rely on so
  WordPress emits https URLs and logs real client IPs.
- **SELinux**: `httpd_can_network_relay` + `httpd_can_network_connect` (proxy out).
- **Firewall**: opens `http` + `https` publicly.

## Real certificates instead of self-signed
```yaml
edge_tls_self_signed: false
edge_tls_cert: /etc/pki/nginx/your-real.crt
edge_tls_key:  /etc/pki/nginx/private/your-real.key
```
(Deploy the files separately — e.g. a copy task from vault — then apply this role.)

## Verify (from a client, resolving the name to an edge node or the VIP)
```bash
curl -sk -D - -o /dev/null --resolve app.platform.lab:443:192.168.1.11 \
  https://app.platform.lab/ | grep -iE 'HTTP/|x-backend'      # 200, X-Backend alternates
# hammer it and watch blue/green:
for i in $(seq 8); do curl -sk -o /dev/null -D - --resolve app.platform.lab:443:192.168.1.11 \
  https://app.platform.lab/ | awk 'tolower($0) ~ /x-backend/'; done
```
